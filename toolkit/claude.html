How to talk to me

  • Bottom line first, then bullets of one sentence each. A lookup gets one line. A decision gets your assessment, the strongest counter, and one recommendation.
  • Be a peer: state assessments as facts, say when I am wrong and why, and say in one line when a claim is sound. If I push back and you change your view, name what changed it.
  • Plain words. Gloss a technical term the first time. Numbers carry units and precision. A claim I could not check myself gets a source.
  • One clarifying question at a time, and only when the answer changes what you do.

Autonomy

  • A question is a question: answer it. Implement only when asked.
  • Cheap and reversible: do it, then report. Irreversible, expensive, or reaching another person: ask first and say what it touches.

What you get

A starting setup for Claude Code that you can fill in and run the same day.

  • A global CLAUDE.md (a note Claude reads at the start of every session) with placeholders.
  • An annotated settings.json.
  • Two hook scripts (small scripts that run on their own at set moments).
  • A slop checker for your writing.
  • Three agents (separate Claude helpers with one narrow job each): researcher, red-team (it challenges a plan from a fresh context) and panelist (a reader for the recipient panel).
  • The memory format I use.

Builds on: petergyang/no-ai-slop (MIT), for slop-check.sh. Notices in the repo.

Setup steps

  1. Read settings.md. If you already have a settings file, back it up with cp ~/.claude/settings.json ~/.claude/settings.json.bak-$(date +%F). Then merge the keys you want from settings.example.json into ~/.claude/settings.json. Register the hooks there as the example shows. The slop-check hook needs jq.
  2. In a code repo, add a map file: copy templates/code-repo/CLAUDE.md and fill it in. Then split your next task across agents using the four rules below.

The four rules and what each part does

How I use AI in the first place is on the How I work page.

The four rules

  1. Split the models by job. The strongest model plans and orchestrates. A mid model writes the code and reviews it. The fastest model does research, recon and intel gathering, because it is fast and cheap for reading. Independent red-teams run on the strongest model. Today that means Opus, Sonnet and Haiku.
  2. One agent per task. Research, recon, planning, coding and review each get their own agent with a narrow brief. Keep each context small.
  3. Review before merge. Coding agents open PRs (pull requests: proposed code changes that wait for review). The red team, one adversarial reviewer with a fresh context, and review agents check them. The orchestrator (the main Claude session that plans the work and merges the results) merges only after that, and I sign off before release.
  4. Add a map of the codebase. A file in the repo covering structure, key files, conventions, and how to run and test. Claude reads it at the start of each session, so it does not rebuild the context every time.

The setup and the reason for each part

Global CLAUDE.md

A file that tells Claude who I am, how I want answers and which evidence rules apply. See the template.

settings.json

Four subagents run at a time and none can start another, so work stays readable.

  • Long sessions compact at 70% of the context window, because a long context costs more and answers worse.
  • A deny list blocks catastrophic commands, force pushes and reads of secret files such as .env, ~/.ssh and ~/.aws.
  • An ask list stops merges, repo deletes, outgoing messages, web fetches and web searches.
  • Each key is explained in the repo.

Hooks

A hook is a small script that runs automatically at a set moment. The repo holds two.

  • One pulls your notes repo when a session starts.
  • One runs a slop check on every markdown and HTML file Claude writes and hands hits back to fix or justify.
  • I also use rtk, an optional tool that shortens command output to save tokens. The hooks README links to it.
  • Hooks in the repo.

slop-check.sh

A script that flags banned words, puffery and sentence patterns I do not want in my writing. It builds on petergyang/no-ai-slop, which its header credits. See the script.

Agents

The repo holds three agents.

  • researcher runs on the fast model and returns a sourced brief under 600 words.
  • red-team runs on the strongest model, writes no files (it can fetch the web) and gives an independent challenge.
  • panelist runs on the fast model with read-only tools and reads a draft as one reader for the recipient panel.
  • All three are in the repo.

Memory

One fact per file, plus an index file with one line per memory.

  • Claude reads the index and opens a file only when it matters.
  • The format is in the repo.

GitHub stop rule

On any 403, 429 or secondary rate limit, all git and gh work stops and the error comes to me. It is one line in CLAUDE.md.
