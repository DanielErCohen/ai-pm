Project start

A new project with an AI agent leaves open who decides, how work is checked and what waits on you. Claude interviews you once and writes the answers into a one-page brief, with the results that would make you stop, and a checklist of what waits on you.

Used in How I work: step 1 and step 3.

Download for Claude Code ZIP

Paste it into a new Claude chat: 12 questions, one at a time, nothing to install.

Where the stop rule came from: on Parapet I took my 7.5 out of 10 quality line from the best earlier score, and no round held it. When a 95% recall line (the share of an estimator's list the AI found) also failed, I replaced the score with a new test instead of stopping, and stopped in Sep '26 before it ran. The rule I took from it: a kill line, the stop result written before the test, comes from the need it serves, and when it fails it triggers stop, pivot or rescope.

Limits: tested by a red team and simulated builders (Claude agents playing new project owners), not yet by a second real project. Checks and guards enforce only in Claude Code.

project/brief.md

What it is

Rebook is a rebooking assistant for independent hair salons. Each week it lists clients who are overdue for their next visit, and the owner sends the salon's own WhatsApp message with two open slots in one tap.

Who it is for

  • First user: owners of salons with one to four chairs.
  • Behaviour that defines them: they keep bookings on paper or a basic calendar and avoid booking platforms because of the commission.
  • Not for now: chains and salons already on a booking platform.

What it does

  1. List the clients past their usual interval each week.
  2. Send the salon's message with two free slots in one tap.
  3. Mark who rebooked.

What it does not do

It does notBecause
Run a booking calendarSalons keep the book they already use.
Take paymentsThe first test needs only a message.
Send a message without the owner tapping sendThe salon stays the sender of every message.

project/owner.md

Waiting on you

1. Recruit five pilot salons

It blocks the first test.

  1. Pick five of the six owners you interviewed.
  2. Ask each to sign the one-page data agreement.
  3. Then ask for their last 50 clients with the date of each last visit.
  4. Agree the message wording with them.

Default: the four owners who named lapsed regulars, plus one more of the six.

Decisions for you

1. First test: each owner sends the messages by hand from the salon's phone for two weeks, or build the weekly list first?

  • Recommendation: by hand with five salons. Demand is the riskiest belief, so it is tested before any code.
  • Strongest counter: a hand-run test cannot show whether owners tap send each week on their own.
  • Default: by hand.

2. Price for the paid pilot: EUR 5 per rebooked client or EUR 19 a month flat?

  • Recommendation: EUR 5 per rebooked client, so a salon pays only for results. Belief 3 tests this price.
  • Strongest counter: a per-client price is hard for an owner to predict each month.
  • Default: EUR 5 per rebooked client.

Privacy block

  • The data: client names, phone numbers and visit dates.
  • Whose it is: the salon's. Rebook and Meta (through the WhatsApp Business API) process it for the salon, and the salon agreement names both.
  • Which tools may see it: the pilot sheet, and later the hosting database.
  • Never pasted: into a chat with an AI tool.

The project, the people and the answers are invented. Beliefs are what must be true for the project to be worth doing. Kill lines are the numbers, written before the test, that decide whether to continue, rescope or stop.

It brings two other tools into a new project: the interview challenges your answers the way product-sparring does, and the Claude Code setup keeps a dated decision log, the short form of a decision record.

Full setup instructions

How to use
  1. In the Claude app, copy the prompt, paste it into a new chat and answer one question at a time.
  2. Save the brief.md and owner.md it returns in a Claude Project's files or a notes app.
  3. In Claude Code, clone or download the repo outside your project, then follow Setup and support.

The Claude app route gives you documents only. Guards (small scripts that run on their own at set moments), skills and review agents install in Claude Code.

Read or edit the prompt
Source and limits

The tool is MIT-licensed. A red team (a fresh Claude session that challenges the work) and simulated builders tested it. Simulated means Claude agents played new project owners. It has not yet started a second real project.

At the end of an install, a verify script runs these checks:

  • No leftover placeholder, "ADAPT" note or unmerged copy of one of your files.
  • No absolute home path and no key-shaped string.
  • Markdown links resolve, shell scripts parse and the settings file is valid JSON.
  • The guard hook passes its own tests, and its push setting matches the merge mode you chose.

Then a fresh Claude agent reads the installed project with no prior context and answers five questions about it. Claude fixes the gaps once.

These checks do not judge whether your answers are right. Hooks and permissions enforce only in Claude Code. The installer copies files and uses no network, remote or account. Model names, commands and tools are dated Oct '26, and the install tells Claude to check them on your machine first.

Setup and support
Why I built itBuilding projects with Claude, I kept finding out late that no one had written down who decides, how work is checked or what waits on me.
  • On Wellness Coach, the iPhone app I am building, review rounds kept chasing small issues while the feature stayed unfinished. The rule is one review round, and a second only to re-check a fix. Anything a person sees is finished in its own change.
  • The owner checklist filled with technical questions. It now holds only what waits on the owner.
  • On Parapet, the B2B tool I stopped in Sep '26, the 7.5 quality line failed and I replaced the score with a new test. Now a failed kill line triggers stop, pivot or rescope, and any change is logged with a date.
  • The interview sizes the setup, so a weekend project does not inherit a team's process.
  • LEARNINGS.md in the repo lists the failures that produced a rule and the file that holds each.

For a team

When more than one person decides, the team module in Claude Code writes down who owns which call.

  • The interview asks who else decides and writes a decision table with a decider and an arbiter per area.
  • It offers four merge modes: solo; Claude merges after checks and review; a person approves; issues only, for a partner who owns the code.
  • In the person-approves mode, an agent review never counts as the approval.

If Rebook had a second founder, project/team.md would start with:

When Lea and Sam disagree, the current state holds until the arbiter answers. After 7 days, the default stated with the question applies and is logged.

Set up in Claude Code

The full install runs in Claude Code, because the guards and skills are Claude Code features. It needs git 2.28 or later, and Git Bash on Windows.

Clone the repo outside your project:

Clone the repo
git clone https://github.com/DanielErCohen/project-start.git ~/project-start

Open Claude Code in your project folder, not in the clone, and paste this line with <path> set to the folder that holds project-start:

Start the interview
Start a project from <path>/project-start/START.md

Claude installs a small core for every project and adds a module, such as sprints, review or privacy, only when one of your answers calls for it.
