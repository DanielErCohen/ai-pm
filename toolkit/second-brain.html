---
name: feedback-keep-source-and-inference-separate
description: When summarising research notes, keep observations separate from interpretations
type: feedback
---

Wholly fictional teaching example. The preference and incidents below were invented for this file.

Keep an observation's source and date beside it. Put an interpretation in a separate sentence and label what remains unknown.

Why: in this fictional workflow, two research summaries turned a participant's request into a claim about the whole customer segment. The source notes described one participant in each session.

How to apply: when summarising a source note, state who was observed by role, the task and the coverage. Label a broader claim as a hypothesis until additional evidence supports it. If the source or date is missing, write "unknown" and leave the claim open for review.

Setup and support
Why I built itI kept re-explaining my context and pasting notes into AI chats, so I moved my notes into a folder Claude reads first.
  • My second brain started in Notion, separate from the AI chats I worked in.
  • Projects in ChatGPT and Claude let me share saved information between chats. I still copied context in by hand.
  • After some months of coding, I moved it to markdown in git (Apr '26). Claude maps, stores and retrieves my notes with a single prompt.
  • Git gives search, history and a diff for every change Claude makes.
  • A weekly sweep archives what is done, because notes pile up and nothing removes them by default.

What you get

An empty template with the structure of my own vault.

  • Five PARA folders for inbox, projects, areas, resources and archive, with an index for areas and one for resources.
  • Four commands: /init briefs a session, /capture files the inbox, /weekly-review runs the hygiene pass and /archive-sweep proposes what to retire.
  • A memory format of one fact per file, each with a Why and a How to apply, plus an index of one line per memory.
  • A log-entry skill that appends a row to a CSV log with the units in the column names.
  • A routine pattern for keeping a scheduled prompt in git, and a session-start hook (a small script that runs on its own when a session starts) that pulls the vault.
  • Three worked examples: log a workout, dictate a story with names checked against a registry, and file the inbox.

Two rules in the instruction file

  1. One fact, one home. A fact lives in one file and other files link to it. No file summarises another, so nothing needs two edits to stay true.
  2. Files state the current conclusion. History is git. A note reads as if it had always been true, and git log holds how it changed.

Three examples

  • Log a workout. In the sample, you say "Ran 4.6 km in 27 minutes, easy" and the log-entry skill appends 2025-10-15,run,4.6,27,easy, to a CSV whose header is date,type,distance_km,duration_min,effort,note. Read the example.
  • Dictate a story. Paste a voice-note transcript. Claude fixes names against registry.md, flags a number that looks misheard and files a dated entry. Read the example.
  • File the inbox. Run /capture. Claude routes five loose notes, leaves two in the inbox and flags the one that holds a password. Read the example.

Copy it

Time to set up: 10 minutes. Pick the assistant you use. The choice is remembered on this device.

The full set: commands, skill, hook and memory setting.

Copy the scaffold and start Claude in it
(
  set -eu
  [ -d "$HOME/how-i-work" ] || git clone https://github.com/DanielErCohen/how-i-work.git "$HOME/how-i-work"
  mkdir "$HOME/my-second-brain"
  cp -R "$HOME/how-i-work/second-brain/scaffold/." "$HOME/my-second-brain/"
  cd "$HOME/my-second-brain"
  mv README.md.template README.md
  mv SOUL.md.template SOUL.md
  git init
  git add -A
  git commit -m "Initial second brain"
)

Set your git name and email if you have not. The command stops if ~/my-second-brain already exists, preserving its files. To resume an existing vault, open that folder in Claude Code. Register the memory folder and session-start pull with the hooks guide.

The 10-minute path

  1. Copy the scaffold and make the first commit (2 minutes).
  2. Fill in .claude/CLAUDE.md. Two language placeholders, then read the two rules (2 minutes).
  3. Register the memory folder and the session-start pull in ~/.claude/settings.json (2 minutes).
  4. Start Claude in the vault and run /init. An empty vault reports almost nothing, which is the right answer (2 minutes).
  5. Drop three loose notes into 00-inbox/ and run /capture. Commit (2 minutes).

What the template leaves out

The template holds no personal content.

  • It is the structure of my own vault with the contents removed.
  • It keeps volatile state out of the instruction file, because a project list there goes stale within weeks.
  • REDACTION.md lists what to keep out of any vault you share.
